# 朱元璋K线人生_教程大纲_v0.2

> v0.1 → v0.2 的变化：应用从「能看」升级到「有节奏」——补入五章闸门、暗夜盘、时间轴连续跟随、触屏适配四项交互层，并完成 B站 Toy 与小站双通道发布。大纲据此重写「制作侧附注」「节奏交互层」「发布链路」三节，配图建议改为按可产出性分类。

## 板块定位

这一板块把朱元璋的一生做成一个动态 Web 应用：用 K 线图隐喻命运、权力、风险和代价的变化。它不是历史论文，也不是金融分析，而是给 Codex 小白看的一个案例——**一个抽象到近乎玄学的创意，怎么被压成一张数据表，再变成能上手玩的网页。**

和前面几个板块相比，这一章的教学重心不在「怎么调接口」或「怎么打包」，而在**创意落地的第一公里**：当你的点子无法直接翻译成功能清单时，先定口径，再谈实现。

成品入口：`apps/zhuyuanzhang-kline/index.html`（单文件，无构建链）
线上地址：B站 Toy `zhu-yuanzhang-kline` · 小站 `/zhuyuanzhang-kline/`

## 观看规则

- 开盘价：阶段起点的处境。
- 收盘价：阶段结束后的处境。
- 最高价：阶段内曾经触及的机会或权力上限。
- 最低价：阶段内承受的风险、危机或代价。
- 冲击量：该事件对人生走势的改变强度。

所有数值都是叙事指数，只用于帮助读者看懂趋势，不代表真实史学定量结论。年龄统一写作「约 X 岁」，按事件年份减出生年份估算，避免把传统虚岁与精确周岁混为一谈。

**这一节是整章的地基**：教程正文必须先把口径讲死，再讲实现。学员最容易犯的错是跳过口径直接让 AI「画个K线」，产出的东西自己也说不清每根线是什么意思。

## 结构与关键事件

27 个年龄切片，覆盖 1328—1398 共 70 年，分五章：

1. **第一章 · 乱世低开**（1328—1347）：贫苦求生，家庭崩塌与入寺。
2. **第二章 · 义军起势**（1352—1360）：投奔郭子兴到建立根据地。
3. **第三章 · 逐鹿天下**（1363—1368）：击败群雄、称帝建明、攻克大都。
4. **第四章 · 洪武定盘**（1370—1387）：分封诸王、重整地方行政、制度副震。
5. **第五章 · 高位余震**（1390—1398）：晚年政治震荡至病逝南京。

同一年可保留多个事件，例如 1344 年的家庭崩塌与入寺、1356 年的攻取集庆与战略收束、1368 年的称帝与攻克大都。

## 制作侧附注

纯 HTML + CSS + Canvas + 原生 JavaScript，不引入构建链，全部内联在单文件里——这也是它能直接发成 B站 Toy 的前提。风格对齐 Above the Web：暖白纸面、细线分隔、宋体标题与克制紫色；为贴合明代主题补入朱砂红、玉绿与金色，但不做重装饰古风。

核心实现分三步：

1. 把历史节点转成结构化数组，每个节点含 `year`、`age`、`title`、`open`、`high`、`low`、`close`、`volume`、`note`。
2. 用 Canvas 按当前视口绘制坐标、影线、实体、命运轨迹、冲击量柱与当前事件高亮。
3. 用 `requestAnimationFrame` 驱动横向跟拍镜头：主线先行、节点随后追上；普通节点快速扫过，重点节点延长停留。只有章节回望与最终收束才主动拉远，普通节点之间不反复改变空间尺度。

播放状态机为五态：**开场命题 / 节点旅行 / 重点停留 / 章节回望 / 全局回望**。镜头目标、揭示进度与叙事卡片分别派生，避免节点切换反向篡改总进度。

响应式用 980px、640px、390px 三层媒体查询；手机端固定为标题、图表、叙事控制、节点轨道四个安全区，Canvas 不与事件卡、年份和按钮争抢空间。

## 节奏交互层（v0.2 新增，本章新的教学重点）

原版是「打开即自动播完」，观众全程被动。这一层的总目标是**增加画面张力**，四项改动都围绕「把节奏交还给观众」：

1. **开场门** —— 不再自动播放。开场停在一颗大号渐变按钮上，按空格或轻点开始；启动后跳过标题黑场直入第一根 K 线。
2. **章节闸门** —— 每章回望卡展示完毕自动暂停，等观众按空格/轻点再进下一章。五章即五次呼吸停顿，终局提示变为「重播一生」。
3. **时间轴连续跟随** —— 底部节点轨道的横向滚动由平滑镜头值逐帧驱动，与图表同步连续滑动，取代原来一节点一次的分段平滑滚动（会互相打断成走停感）。
4. **密度与默认速度** —— 可视跨度加大，运动中能同时看到更多前后节点；年份标签阈值放宽；默认播放速度 1.3 倍。

配色扩为四套：**暮山紫**（默认）、**宫墙朱**、**山水墨**、**暗夜盘**，控制条上有月亮键在暗/亮之间一键互切。设置面板集中开放播放速度、镜头特写、背景纹理、波动区间底色、轨迹光点、节点声音与配色；同一组能力暴露为 `window.klineControls.getSettings()`、`setSettings()`、`resetSettings()`，便于教程演示代码控制。

**两个可直接进正文的坑：**

- **减弱动画 ≠ 跳过交互。** 初版为 `prefers-reduced-motion` 写了「直接跳过开场、置为已开始」的分支，导致开了系统减弱动画的机器打开即停在第一根 K 线，开场门形同虚设。减弱动画只应少动画，不应跳过交互门。
- **触屏没有空格键。** 「按空格继续」在手机上无从触发，且等待态弹窗是 `pointer-events: none`。修法是等待态放开点击、文案按 `(pointer: coarse)` 自适应成「轻点」，空格监听保留，两种输入并存。

## 发布链路

单文件自包含 → 直接作为 B站 Toy 上传（`toy create` 先出预览链接，确认后加 `--yes` 提交审核）；同一份文件拷进小站 `public/` 子路径，push 触发构建部署。发布后**立刻把 Toy 项目 id 记进仓库**——以后更新全靠它，这条纪律与台风板块坑二同源。

## 教程展开建议

正文按「**先收束隐喻 → 再定数据口径 → 再做交互页 → 最后调节奏**」四段推进。重点不是讲 Canvas API 的每个细节，而是让学员看到：模糊创意先被压成一张数据表，再由 Codex 生成可视化结构，最后通过自检与真机试玩修掉可读性与节奏问题。

节奏层尤其适合讲「**AI 做得出功能，但节奏要人来定**」——四项改动没有一项是技术难点，全部来自「自己看一遍觉得不对劲」。
