# 台风实时预测 · 教程大纲 v0.1（2026-07-17，待作者审核）

> 定位：《120min Codex小白系列教程》「台风实时预测」实战板块正文大纲。
> 素材来源：「风眼 Typhoon Eye」完结项目——本地仓库 `E:\typhoon-eye`（PLAN.md / README / index.html / scripts / toy.yaml）+ 约 73 个开发提交的 git 历史（已过滤 `data:` 定时噪音）+ 三篇复盘（云端定时连环坑「全绿不等于已发」、B站 Toy 同步事故「版本指纹与外部 cron 兜底」、三环断裂排障公开版）。

>
> 核心卖点（开篇一句话）：**不写一行代码，跟 Codex 聊着天做出一个每 15 分钟自动更新的台风实况网站，再把它发布成 B站 Toy——这个站上线后还拿到了 B站官方推流。**

## 第 1 节 · 先认识你的建站班底

> 写法：每位成员一张小卡片——「它是谁 + 在这个项目里管什么」，各 2-3 句话打住，不讲内部怎么实现。

| 成员 | 一句话身份 | 本项目分工 |
|---|---|---|
| **GitHub 仓库 + Pages** | 代码的家 + 免费网址 | 存网站文件；自动给你一个全世界都能访问的网址 |
| **GitHub Actions** | 全天候数据工人 | 每 15 分钟替你抓一次台风数据存进仓库，网站永远显示最新实况 |
| **bili-toy-publisher**（skill） | B站发布助理 | 负责把网站打包、体检、发布/更新成 B站 Toy |

## 第 2 节 · 建站实操：从一句话到台风站上线

> 主线五步，每步 = 一段对话提示词 + 一张结果截图，「对话 + 结果」呈现，不解释背后发生了什么。

### Step 1 · 一句话立项

- 提示词模板：
  > 「我想做一个台风实况信息 + 分级应急预案的单页网站，给沿海居民用：台风叫什么、在哪、多强、往哪走、我该做什么，一屏答完。先帮我写份计划书、建好仓库」
- 学员只审计划书 2 处：①功能范围是不是自己想要的；②有没有写清「本站不是预警发布渠道，以官方为准」的免责红线
- 结果展示：计划书（PLAN.md）截图 + 新仓库页面

### Step 2 · 搭出第一版页面

- 提示词模板：
  > 「按计划书把页面搭出来：实况面板、路径示意图、蓝黄橙红四级预警各配一份可勾选的行动清单、昼夜双主题。先用演示数据，页面上标明『演示』」
- 一句话点到：先用假数据把页面跑通，真数据下一步再接——顺序别反
- 结果展示：demo 页面截图（带「演示」横幅）

### Step 3 · 让 Codex 自己当质检

- 提示词模板：
  > 「按计划书里的验收清单自审一遍：控制台报错、手机小屏、深浅主题、勾选后刷新还在不在。发现 bug 直接修，修完给我报告」
- 本案例实况：Codex 自审揪出 3 个显示 bug（当前位置点颜色不对、悬浮提示位置漂移、地图边缘提示被裁掉），全部自己修掉
- 学员只读报告结论，点头即过
- 结果展示：自审报告对话截图

### Step 4 · 接真实数据，网站上线

- 提示词模板：
  > 「接入浙江省台风路径实时发布系统的真实数据，用 GitHub Actions 每 15 分钟自动抓一次；抓不到时降级显示演示数据并标明。然后发布到 GitHub Pages 上线」
- Codex 会产出抓取脚本 + 定时任务，学员的活只有一个：打开线上网址确认页面能看
- 一句话贴士（避坑预告）：上线后巡检**看页面上的数据时间**，别只看 Actions 的绿色对勾——为什么，第 3 节坑一细说
- 结果展示：线上 Pages 页面截图 + Actions 运行列表截图

### Step 5 · 发布成 B站 Toy

- 提示词模板：
  > 「用 bili-toy-publisher 把网站打包成 B站 Toy：先做手机端适配、配一张封面，体检通过后给我上传包」
- 发布动作在 B站发布平台网页端完成（登录后上传 ZIP，点发布），过审约 10 分钟
- 发布成功后的第一件事：让 Codex 把 Toy 的**项目 id 记进仓库**（一句话交代：以后更新全靠它——第 3 节坑二就是没记 id 的血泪）
- 结果展示：Toy 线上页面截图 + 发布记录截图

**需要素材**：5 步各 1-2 张对话/结果截图（其中 Step 2 的 demo 页需回退到历史版本补截）

## 第 3 节 · 上线之后：三个「怎么不更新了」

> 写法：每个坑 = 症状一句话 + 一句对话解法，全部来自本项目真实事故，不讲原理。

1. **坑一 · 全绿不等于已发**：Actions 页面一片绿对勾，线上数据却停更了两天。巡检口诀只有一句——**看页面右上角的数据时间，别看绿灯**。对话解法：「帮我加一个守护任务：数据过期了才动手补抓，平时空转」
2. **坑二 · Toy 永远停在第一版**：仓库里改了好几版，B站上还是首发版。让 Codex 一步定性：「抓一下线上页面，看看版本号是多少」——网址里的 `-v1` 就是铁证：发布后从没更新成功过。根治动作呼应 Step 5：发布完立刻记 id，每次更新后确认版本号 +1 才算数
3. **坑三 · GitHub 的闹钟会丢班**（选配）：定时任务每小时该跑 4 班，高峰期只被放行 1 班，官方状态页还全绿。对话解法：「配一个 cron-job.org 外部闹钟，每 15 分钟戳一下守护任务兜底」——本项目这条兜底上岗第一次执行就真实补救了一次丢班
- 一句话彩蛋贴士：页面里的应急电话在 B站 App 里点不动？那是平台沙箱的限制，源码里已带修复，教程不展开
- 收尾一句话：网站上线只是开始——数据自己更新、坏了有人兜底，这套「建站 + 保活」流程，你的下一个数据类网站照抄即可

**需要素材**：三个坑各 1 张定性截图（线上外壳 `-v1` 网址、Actions 丢班运行记录、cron-job.org 执行记录）
